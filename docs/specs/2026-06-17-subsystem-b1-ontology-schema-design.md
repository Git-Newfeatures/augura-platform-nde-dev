# Subsystem B1 — Ontology/causal schema + seed + read API — Design

**Date:** 2026-06-17
**Status:** Proposed (awaiting review)
**Part of:** Subsystem **B** (semantic enrichment + ontology causal). B decomposes into **B1** (this — ontology foundation) → B2 (`dag-llm`) → B3 (`picot-parse`) → B4 (`enrich-propose/apply`) → B5 (frontend). B1 is **A1-shaped**: schema + seed + read API, **no LLM**.

## Context

A1 ported the DQ-subset of the MVP `semantic` schema. B1 ports the **remaining ontology/causal tables** the MVP migration defines — the substrate B2 (`dag-llm`) and B4 (`enrich`) consume. Seed data exists in the MVP repo (`/tmp/augura-src/obsolete/standards/*.csv`). Reuses A1's exact patterns: global read-only reference tables in `public`, `FOR SELECT` RLS, seed generated by the committed `gen_semantic_seed.py`, vertical-slice read endpoints in the existing `semantic` module.

## Goals
1. Add 8 ontology/causal tables to the bundle (`public`), RLS read-only, seeded from the MVP CSVs.
2. Extend `gen_semantic_seed.py` to emit these tables; append to `seed.sql`.
3. Extend the `semantic` module: ORM models + repo methods (for B2/B4 to consume) + minimal read endpoint(s) (`GET /semantic/relations`).
4. api-client regen; real-DB validation.

## Non-goals (deferred to later B slices)
- `dag-llm` (B2), `picot-parse` (B3), `enrich-propose/apply` + versioning workflow (B4), frontend (B5), LLM of any kind.
- `semantic.releases` versioning table → B4 (enrich needs it; B1 keeps the static `version`/`review_status`/`active` columns, seeds a constant).

## Architecture

### Tables (added to `schema.sql`, `public`, ported from the MVP migration, `semantic.`→public, FKs to `taxonomy_concepts` kept)
| Table | PK | Seed CSV |
|-------|----|----|
| `causal_predicates` | `predicate_id` | causal_predicates.csv |
| `dq_predicates` | `predicate_id` | dq_predicates.csv |
| `ontology_relations` | `relation_id` | ontology_relations.csv (subject/object → taxonomy_concepts; predicate, polarity, default_strength, default_temporal_lag, mechanism_summary, review_status, version, active) |
| `ontology_relation_evidence` | `evidence_id` | ontology_relation_evidence.csv (relation_id FK, source_type, citation_or_url, evidence_summary, population_notes, evidence_strength, review_status) |
| `ontology_relation_qualifiers` | `qualifier_id` | ontology_relation_qualifiers.csv |
| `taxonomy_relationships` | `relationship_id` | taxonomy_relationships.csv (from/to_concept_id → taxonomy_concepts) |
| `taxonomy_therapeutic_areas` | (composite local_concept_id, therapeutic_area) | taxonomy_therapeutic_areas.csv |
| `taxonomy_standard_codes` | (composite local_concept_id, vocabulary_id, concept_code) | taxonomy_standard_codes.csv |

DDL ported verbatim from `/tmp/augura-src/supabase/migrations/20260610000000_create_semantic_schema.sql` (lines 59–203), stripping `semantic.` and keeping the `references taxonomy_concepts(local_concept_id)` FKs (taxonomy_concepts exists from A1, created first in schema.sql). Order so FK parents precede children (relations before evidence/qualifiers).

### RLS (`policies.sql`)
All 8 are global read-only reference tables → the A1 `backend_read` `FOR SELECT` gate pattern (explicit per-table `alter` + `create policy backend_read ... for select using (app.tenant_id is not null)`). Add to `EXPECTED_TABLES` (and NOT `RLS_REQUIRED`, since they're reference-gated like the A1 taxonomy tables).

### Seed
Extend `apps/api/scripts/gen_semantic_seed.py`'s `TABLES` list + `BOOL_COLS`/`NUM_COLS` maps with the 8 tables (booleans: `ontology_relations.active`, `ontology_relation_qualifiers.is_hard_constraint`). Re-run against `/tmp/augura-src/obsolete/standards/` and append the output to `seed.sql` under a `-- ontology/causal (B1)` section. Same "reconstructed from obsolete/standards, swap-later" caveat as A1.

### `semantic` module extension
- `models.py`: add ORM for the 8 tables (only columns B2/B4 read; module never writes).
- `repo.py`: `list_relations(active=True)`, `list_relation_evidence()`, `list_causal_predicates()`, `list_relationships()`, `relations_for_concepts(ids)` (the subgraph query B2 needs: relations whose subject or object ∈ ids).
- `schemas.py`: `RelationOut` (relation_id, subject_concept_id, predicate, object_concept_id, polarity, default_strength, mechanism_summary, active).
- `router.py`: `GET /semantic/relations` (optional `?concept_id=` filter → subgraph). Other tables repo-only until B2/B4 need endpoints.

## Testing
- **DB bundle:** 8 tables in `EXPECTED_TABLES`; seed asserts (`insert into ontology_relations`, `causal_predicates`); RLS `backend_read` per table; generator emits them.
- **Generator unit test:** extend with one of the new tables (booleans/nulls).
- **Unit (service):** `relations()` maps rows; `relations_for_concepts` filters by subject/object.
- **Route:** `GET /semantic/relations` in OpenAPI + 401.
- **Integration (DB):** after seed, `list_relations` returns rows, `relations_for_concepts` filters; RLS read-only.
- **api-client** regen; **real-DB validation** (apply bundle → counts: ontology_relations > 0, causal_predicates > 0).

## Acceptance criteria
1. 8 ontology/causal tables in the bundle (`public`), RLS read-only, seeded.
2. `gen_semantic_seed.py` emits them; `seed.sql` updated.
3. `GET /semantic/relations` (+ `?concept_id=` subgraph) returns the documented shape; repo methods for B2/B4 exist.
4. api-client regenerated; drift-check green.
5. Real-DB validation green (counts > 0; RLS read-only).

## Risks / open items
- **Seed authenticity:** obsolete/standards CSVs (flagged; swap later). The `concept-frontier.json`/`causal-learning-set.json`/`enrichment-proposals.json` in `scripts/` are enrichment *inputs/outputs*, not the canonical ontology — B1 seeds from the CSVs.
- **FK integrity:** ontology_relations subject/object FK `taxonomy_concepts` — the seed concepts (A1) must cover the relation endpoints. If a relation references a concept absent from the A1 seed, the FK insert fails. Mitigation: the generator/validation will surface it; if so, either seed `ON CONFLICT`/filter dangling relations or drop the FK to a soft reference (decide at implementation from the actual data).
- **Reconciliation with `/agents/dag`** is a B2 concern, not B1.
